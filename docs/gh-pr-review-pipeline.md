# GitHub PR Review Pipeline

Разработка идёт напрямую в `main`. На каждый push GitHub Action создаёт snapshot PR для code review (Codex).

## Как работает

1. Push в `main` триггерит `.github/workflows/review-snapshot-prs.yml`
2. Для каждого коммита создаётся неизменяемая snapshot-ветка `rv/<task-id>/<short-sha>`
3. PR создаётся между snapshot текущего коммита и snapshot предыдущего → diff ровно одного коммита
4. Codex автоматически ревьюит PR
5. По итогам Codex либо оставляет inline-комментарии (замечания), либо ставит approve (emoji). Если комментариев нет — код чистый

Task ID извлекается из commit message по regex `[A-Z]+-[0-9]+`. Если нет — `misc`.

PR существуют только для review. Не мержить. После обработки комментариев — закрывать.

## Политика триажа review-комментариев

Автоматические ревью генерируют много комментариев. Не все полезны.

**Принимаем и фиксим:**
- Race conditions, data loss, некорректная логика
- Реальные баги (edge cases, которые случаются на практике)
- Security issues

**Отклоняем с объяснением:**
- "Добавьте валидацию X" — когда X уже ограничен UI или вызывающим кодом
- Гипотетические edge cases, требующие значительного рефакторинга
- Pre-check, дублирующий downstream error handling
- "Форма не сохраняет данные" — когда это осознанный placeholder
- Предложения усложнить код ради теоретической robustness

**Принцип:** не усложнять код ради удовлетворения review-бота. Простота важнее 100% coverage edge cases.

На каждый комментарий: реакция (+1 / -1) + reply с объяснением.
